## Итоговый вопрос

Процессору выгодно загружать из RAM сразу целый блок соседних данных (кэш-линию, обычно 64 байта = 16 int), потому что:
1. **Кэш** — быстрая память между CPU и RAM. Одно обращение к RAM стоит десятки-сотни тактов, а к кэшу L1 — единицы.
2. **Кэш-линия** — минимальная единица обмена с RAM. Загрузив 64 байта один раз, процессор получает 16 соседних int «бесплатно».
3. При **последовательном доступе** следующие элементы уже лежат в кэше → почти все обращения — попадания (cache hit).
4. При **большом шаге** из каждой линии используется только 1 элемент, остальные 15 выбрасываются → каждое обращение идёт в RAM (cache miss) → программа замедляется.

## Контрольные вопросы

1. **Зачем процессору кэш-память?** CPU работает в разы быстрее RAM. Кэш сглаживает эту разницу: хранит часто используемые данные рядом с процессором и не даёт ему простаивать в ожидании RAM.

2. **Чем кэш отличается от RAM?** Кэш меньше по объёму (КБ–МБ против ГБ), но значительно быстрее (latency единицы тактов против сотен), дороже за байт и физически расположен на кристалле CPU или рядом с ним.

3. **Что такое кэш-линия?** Минимальный блок данных, который кэш загружает из RAM за одно обращение. У современных x86 — 64 байта (16 значений int).

4. **Почему последовательный доступ удобнее?** При чтении элемента i в кэш попадают элементы i+1…i+15. Следующие 15 обращений — попадания в кэш. При большом шаге (например, 16) каждое обращение попадает в новую линию, и 15/16 загруженных данных пропадают зря.

5. **Почему результаты отличаются при разных запусках?** Влияют: фоновые процессы Windows, турбо-буст и троттлинг CPU, миграция потока между ядрами, состояние кэша на момент старта, JIT-компиляция, энергосбережение. Поэтому ориентируются на общую закономерность, а не на одно число.
